# Design Doc: Hook Referential Stability Optimization (Phase 4.1.1)

**목표**: `useGolfRecord` 훅의 구조를 개선하여 불필요한 리렌더링을 방지하고, 대규모 상태 변화에도 UI 응답성을 유지합니다.

---

## 1. 현상 분석 (Current Issues)

현재 `useGolfRecord`는 다음과 같은 성능 저하 요인을 가지고 있습니다:

1. **Shallow Merge Return**: `{ ...state, ...actions }` 형태로 반환하여, 상태가 하나만 변해도 반환 객체의 메모리 주소가 매번 바뀝니다.
2. **Unstable Actions**: `setPar`, `setStroke` 등 대부분의 액션 기능이 `state.par`, `state.stroke`와 같은 개별 상태값에 의존성을 가집니다.
    * 예: `par`가 바뀌면 `setPar` 함수가 재생성되고, 이를 전달받는 UI 컴포넌트들이 `React.memo`를 사용하더라도 함수 주소 변경으로 인해 리렌더링됩니다.
3. **Complex Action Creators**: `handleSaveCurrentHole`과 같은 복잡한 로직이 `state` 전체를 의존성으로 가져, 거의 모든 사용자 인터랙션 시 함수가 재생성됩니다.

---

## 2. 개선 아키텍처 (Refined Architecture)

### 2.1. State/Actions 분리

반환 구조를 2-Layer로 격리합니다.

```typescript
// AS-IS
const { currentHole, setPar, ... } = useGolfRecord();

// TO-BE
const { state, actions } = useGolfRecord();
// 사용 시: state.currentHole, actions.setPar()
```

### 2.2. Stable Action Pattern

모든 액션 함수는 `dispatch`에만 의존하며, 절대 재성성되지 않는 **고정 주소**를 가집니다.

* **배경**: `useReducer`의 `dispatch`는 React에서 생명주기 동안 안정성이 보장됩니다.
* **방법**: 액션 함수 내부에서 현재 상태가 필요한 경우, `useCallback` 의존성에 상태를 넣는 대신 **함수형 업데이트(Functional Updates)** 패턴을 지향하거나, `dispatch`의 페이로드를 강화하여 Reducer 내부에서 판단하게 합니다.

```typescript
// 예시: setPar의 안정화
const setPar = useCallback((v: number | ((p: number) => number)) => {
  dispatch({ type: 'UPDATE_SCORE_FIELD', payload: { par: v } });
}, [dispatch]); // 의존성은 오직 dispatch뿐
```

---

## 3. 상세 변경 사항

### 3.1. `golfRecordReducer` 고도화

* `UPDATE_SCORE_FIELD` 등에서 함수형 업데이트를 지원하도록 수정.
* `SET_HOLE` 등 복합 상태 변경 로직의 정교화.

### 3.2. `useGolfRecord` Hook 수정

* 모든 `useCallback`의 의존성 검토 및 최소화.
* `actions` 객체를 `useMemo`로 감싸되, 의존성을 빈 배열(`[]`) 또는 `[dispatch]`로 설정.

### 3.3. `RecordScreen` (app/(tabs)/record.tsx) 마이그레이션

* 구조 분해 할당 로직 수정 (`const { state, actions } = useGolfRecord()`).
* JSX 내 참조 경로 수정 (예: `par` -> `state.par`).

---

## 4. 예상 사이드 이펙트 및 대책

* **Side Effect**: 구조 분해 누락 시 런타임 에러 발생 가능.
* **대책**: 수정 즉시 `tsc` (TypeScript Compiler) 및 린트 체크를 통해 모든 참조 오류를 자동 검출하고 수정합니다.

---

## 5. 단계별 실행 계획

1. **Step 1**: `useGolfRecord.ts`에서 `actions`를 별도 객체로 분리하고 `dispatch` 기반으로 안정화. (반환 타입 정의 포함)
2. **Step 2**: `RecordScreen.tsx`에서 바뀐 구조에 맞춰 데이터 바인딩 수정.
3. **Step 3**: 린트 및 타입 체크 (`npm run lint`, `tsc`) 실행하여 무결성 확인.
